## 1. 프로젝트 개요

이 프로젝트는 채용 공고 탐색, 회원 인증, 마이페이지, 이력서 관리, 채용 공고 상세 조회 및 일정 관리를 제공하는 React 기반 프론트엔드입니다.

- 프레임워크: React 19, Create React App
- 라우팅: React Router DOM 6
- 데이터 검증: Zod
- API 연동: CRA proxy를 통한 `http://localhost:8080` 연결
- 테스트: Jest, React Testing Library
- 주요 구조: `api` → `hooks` → `components` → `pages`

## 4. 현재 화면 및 라우트

| 경로 | 화면 | 인증 필요 |
| --- | --- | --- |
| `/`, `/jobs` | 채용 공고 목록 | 아니요 |
| `/jobs/:jobNoticeId` | 채용 공고 상세 | 아니요 |
| `/calendar` | 지원 일정 캘린더 | 현재 라우트상 아니요 |
| `/auth` | 로그인 및 회원가입 | 비로그인 사용자용 |
| `/mypage` | 마이페이지 | 예 |
| `/resume/new` | 새 이력서 작성 | 예 |
| `/resume/:resumeId` | 이력서 조회 및 수정 | 예 |

인증된 사용자가 `/auth`에 접근하면 `/jobs`로 이동하고, 인증되지 않은 사용자가 마이페이지나 이력서 경로에 접근하면 `/auth`로 이동합니다. 정의되지 않은 경로는 `/`로 이동합니다.

## 7. 기록 해석 시 참고사항

- 이 문서는 Git에 기록된 이력을 기준으로 작성했으므로, 커밋 전에 덮어쓴 세부 작업 과정은 복원할 수 없습니다.
- 병합 커밋은 기능 구현을 중복 설명하지 않고 브랜치 통합 시점으로 기록했습니다.
- 정리 시점의 작업 트리는 깨끗하며, 별도의 미커밋 변경 사항은 없습니다.
- 이후 변경은 같은 형식으로 날짜, 커밋 ID, 기능 목적, 주요 변경 파일 및 테스트 내용을 이어서 기록하면 됩니다.

## 8. 커밋 메시지 작성 권장 형식

앞으로 로그를 일관되게 유지하려면 다음 형식을 권장합니다.

```text
[Add] 기능명: 새 기능 설명
[Fix] 기능명: 수정한 문제 설명
[Refactor] 기능명: 동작 변경 없는 구조 개선
[Test] 기능명: 추가 또는 수정한 테스트
[Docs] 문서명: 문서 변경 내용
```

예시:

```text
[Fix] Calendar: 월 이동 시 선택 날짜 초기화 오류 수정
```
